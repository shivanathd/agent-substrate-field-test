Agent Substrate, frozen and thawed

Google's open-source runtime freezes idle AI agents into a storage bucket and thaws them onto any free machine. We stood it up on GKE from nothing, ran real Claude Code agents on it, checked its security claims, benchmarked it with its own harness and priced it against hosted sandboxes.

What held up

Holds
State survives a freeze

20 of 20 cycles came back with memory, files and root filesystem exact, across three different workers.

Holds
Real coding agents can be frozen mid-task

Three Claude Code agents resumed with their in-memory loop counters intact, one on a different node, and kept getting answers from Claude.

Partly
“Sub-500 ms resume”

True for a small agent (0.22 s). A 1 GiB agent takes 3.50 s; a 2 GiB agent 6.90 s, or 16.0 s under microVM isolation.

Holds
Oversubscription without errors

15 agents on 10 workers: 2,123 requests, zero failures. Sleep slows down under load; wake barely moves.

Holds
Agents can use keys they never hold

The egress gateway injected a secret into an outbound request; the secret was nowhere in the agent's environment, processes or filesystem.

Fails
Secrets an agent does hold are safe at rest

Memory snapshots are not encrypted. The demo's API key was in them 77 times.

Depends
Cheaper than the alternatives

9× cheaper than one pod per agent at 5% awake. But a hosted sandbox that doesn't bill while paused (E2B: $1,511/month) beats Substrate on on-demand nodes ($2,303); Substrate wins on spot nodes ($1,056).

Who should care

  • Hundreds of stateful, mostly idle agents (one per user, customer or ticket) on a team that already runs Kubernetes: the core works today and the economics hold below about 25% awake.
  • A handful of agents, or busy ones: a Deployment or a hosted sandbox is simpler and no more expensive.
  • Everyone: inject credentials at the edge instead of handing them to agents. Snapshots keep whatever an agent holds.

Not a scale test (two nodes), not a production review, not affiliated with the Substrate project or Google.

How these were measured

Upstream's own Locust harness, running in-cluster as a Kubernetes Job, so no laptop or WAN in the path. Each run is an unmodified entry from upstream's benchmark catalogue; the memory entries were also run for 5 minutes instead of 1 because a 2 GiB agent only fits a few cycles a minute. glutton holds a fixed amount of memory and re-reads all of it after every wake, the worst case for lazy page loading. 18 runs, 4,717 requests, 0 failures.

1,000 agents a month, five ways

Each agent gets 0.5 vCPU and 1 GiB when awake. Substrate needs enough nodes for the agents awake at once with 2× headroom, plus one for the control plane. Hosted sandboxes bill per second while running.

  • Against one pod per agent, Substrate is 9× cheaper at 5% awake, 2× at 25%, and no cheaper at 50%.
  • Against hosted sandboxes that stop billing when paused (E2B, Daytona), Substrate on on-demand nodes costs more at every duty cycle we modelled. Hosted pricing has no headroom or control-plane overhead.
  • Substrate wins on spot nodes (about 60% off), which suit it because agents already live in snapshots. We did not test spot: a reclaimed node leaves its agents CRASHED until reverted.
  • What the numbers leave out: running Postgres, the router, the gateway and node agents yourself; committed-use discounts; data residency and VPC control, which are the usual reasons to self-host.

What we ran

A request reaches an agent through the router, which wakes it onto a worker pod if it is asleep. The node agent checkpoints and restores agents to the bucket. Every outbound connection goes through the egress gateway, which enforces the allow-list and injects credentials.

How the test ran, including what broke

From an empty GCP project to published results. The bottom lane is every failure we hit and how it was fixed.

Setup refuses to touch a project or Substrate checkout it did not create, and teardown refuses any project without its label. Run it from a cloud VM in the same region and most of the build and download time disappears.

Credentials injected at the edge

A random secret went into a Kubernetes Secret. The agent called an in-cluster echo server with Authorization: placeholder. Eight checks, all passed:

  • The server received Bearer <secret> and never saw the placeholder.
  • The request arrived from the egress gateway pod's IP, not the agent's.
  • The secret was absent from the agent's environment, every /proc/*/environ, and a full filesystem search (which we confirmed actually ran).
  • HTTPS to a host the policy doesn't cover was refused, and the same request succeeded once the policy allowed it, so the policy did the refusing.

An agent with no egress policy has all traffic blocked, DNS included. That is why the upstream Claude Code demo can't reach Claude as shipped.

Snapshots are RAM in a bucket

A memory snapshot is the agent's memory, compressed and written to object storage. Substrate does not encrypt it. The upstream demo passes its API key as an environment variable, so we unwrapped its snapshots and counted.

41 54 45 53 50 52 53 45 02 00 00 00 28 b5 2f fd …   ATESPRSE v2  zstd frame

Every snapshot object starts like this: an 8-byte magic, a version, then a plain zstd stream.

  • 77 copies of the full key across 12 snapshot objects: the template's shared base image, each agent's own delta, and checkpoint metadata.
  • Read access to the bucket is read access to every secret any agent held in memory.
  • Fix: inject credentials at the gateway so agents never hold them, and treat the bucket as a secret store anyway (customer-managed keys, tight IAM, access logs).

Other rough edges

  • Alpine-based agents couldn't resolve example.com inside the sandbox; example.com. with a trailing dot worked. Node-based agents were fine.
  • When a worker pod disappears, its agents go to CRASHED and wait for a manual revert.
  • Every image builds from source on the operator's machine; on Apple silicon that is amd64 under emulation.
  • The microVM installer needs a zstd binary it doesn't list, and finds out after a 924 MB download.

Nine items, with reproduction steps, are written up for the maintainers in docs/upstream-issues.md.
